# Первый коммит {#first-commit}

Коммит состоит из снимка выбранных файлов, автора, времени и сообщения. Сначала файлы попадают в **индекс** (staging area), затем Git записывает из индекса коммит.

## Проверка изменений

В Source Control выберите любой текстовый файл. Откроется редактор различий (diff). Для нового файла одна сторона сравнения пуста, а весь текст отмечен как добавленный.

Бинарные файлы, например `.png`, `.xlsx` и `.rds`, Git сохранит, но не покажет построчное сравнение. Перед коммитом откройте их обычным способом и убедитесь, что это нужные файлы.

![Редактор различий Positron для нового текстового файла из проекта r-course и список Changes в Source Control]()

## Добавление в индекс

Наведите указатель на заголовок **Changes** и нажмите `+` (**Stage All Changes**). Файлы переместятся в раздел **Staged Changes**.

Проверьте список ещё раз. В первый коммит должны войти все накопленные файлы проекта, кроме уже скрытых правилами `.gitignore`.

## Запись коммита

Введите сообщение:

```text
Зафиксировал результат курса R
```

Нажмите **Commit**. Если Positron попросит настроить автора, вернитесь к главе \@ref(git-identity).

![Source Control сразу после исходного коммита: разделы Changes и Staged Changes пусты, в Graph виден один коммит]()

Пустой список изменений означает, что рабочая папка совпадает с последним коммитом. Старые файлы никуда не переместились: Git только записал их состояние.

::: {.callout .callout-info}
Сообщение коммита отвечает на вопрос «что сделал этот шаг?». Короткая форма с глаголом помогает читать историю: «Добавил импорт данных», «Исправил подпись оси».
:::
