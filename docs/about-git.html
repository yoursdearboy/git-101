Глава 2 Зачем проекту Git

В проекте анализа данных меняются код, текст отчёта и графики. Копии с названиями final, final-2 и really-final сохраняют файлы, но не объясняют, кто и зачем их менял.

Git хранит коммиты — снимки выбранных изменений с коротким пояснением. Из них складывается история проекта. По ней можно:

  • сравнить текущую работу с предыдущей версией;
  • вернуть исправный вариант;
  • вести несколько вариантов анализа в ветках;
  • объединять изменения разных участников.

Git работает локально. Для коммитов не нужны интернет и аккаунт. GitHub понадобится позже как удалённое место для общей истории и обсуждения изменений.

2.1 Что уже есть в проекте

Откройте папку r-course, созданную в предыдущем курсе. Не создавайте новый учебный проект и не переносите файлы.

В проекте могут оставаться .R-скрипты, report.qmd, analysis.qmd, другие документы, папки data и out. Это ожидаемое состояние. Git умеет отслеживать любые файлы; расширение не нужно менять ради Git.

Новый код этого курса будем писать в paper.qmd. Так текст, команды R и результат останутся в одном воспроизводимом документе Quarto.

2.2 Репозиторий

Репозиторий — папка проекта вместе со скрытой служебной папкой .git. В .git находится история, ветки и настройки связи с удалённым репозиторием.

Шаблон R Project в Positron создаёт .git и .gitignore автоматически. Поэтому проект из R-курса уже должен быть репозиторием, хотя в нём пока нет коммитов. В главе 5 мы это проверим.
