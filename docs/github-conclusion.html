Глава 18 Итог работы с GitHub

Теперь вы умеете:

  • публиковать локальный репозиторий через Publish to GitHub;
  • входить в GitHub через браузер;
  • различать Push, Pull, Fetch и Sync Changes;
  • публиковать отдельную ветку;
  • создавать, проверять и сливать pull request;
  • клонировать проект командой Workspaces: New Folder from Git….

Для обычной работы достаточно короткого цикла: Pull → новая ветка → небольшие коммиты → Push → pull request → проверка → merge.

GitHub — не резервная копия незакоммиченных файлов. Пока изменение не вошло в коммит и не отправлено, оно существует только в вашей рабочей папке.
