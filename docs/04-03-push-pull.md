# Push, pull и синхронизация {#sync-remote}

Локальная и удалённая копии меняются независимо. Три операции поддерживают их в согласованном состоянии.

| Действие | Результат |
|---|---|
| **Push** | Отправляет локальные коммиты на GitHub |
| **Pull** | Загружает удалённые коммиты и объединяет их с текущей веткой |
| **Sync Changes** | Сначала выполняет pull, затем push |

Эти определения соответствуют официальной документации [Working with repositories and remotes](https://code.visualstudio.com/docs/sourcecontrol/repos-remotes).

## Небольшая проверка

Добавьте после заголовка `paper.qmd` одно предложение о цели анализа. Сохраните файл, проверьте diff и создайте коммит `Уточнил цель анализа`.

В строке состояния появится исходящий коммит `↑1`. Нажмите **Sync Changes**. После синхронизации счётчик исчезнет, а коммит появится на GitHub.

## Перед началом работы

В совместном проекте начинайте с **Pull**, а заканчивайте **Push**. Так вы раньше увидите чужие изменения и реже столкнётесь с конфликтом.

**Sync Changes** удобно, когда вы понимаете обе половины операции. Если нужно отдельно проверить входящие коммиты, выполните **Fetch**, посмотрите их в Source Control Graph и только затем нажмите **Pull**.

Если push отклонён, обычно удалённая ветка содержит новые коммиты. Не применяйте force push. Сначала выполните Pull, разрешите возможный конфликт и повторите Push.
