Глава 7 Рабочий процесс

В предыдущей главе мы научились создавать коммиты (версии). Работая с Git, это нужно делать регулярно — обычно после выполнения задачи или её части, после внесения исправлений или просто чтобы зафиксировать изменения. Коммит сохраняет «стабильную» версию проекта, к которой можно вернуться или сравнить с ней изменения.

Рассмотрим процесс работы над проектом подробнее:

  1. В рабочей папке загружен коммит и нет посторонних изменений.
  2. Выполняем задачу и добавляем нужные изменения в индекс, а лишние убираем.
  3. Перед созданием коммита обязательно проверяем изменения. Начинающие пользователи часто либо добавляют ненужный код, не относящийся к задаче, либо забывают добавить код, без которого не будет работать остальная часть проекта.
  4. Создаём коммит и получаем чистую рабочую папку — без изменений относительно нового коммита. Можно переходить к следующей задаче.

Такой процесс помогает упорядочить внесение изменений и сделать результат воспроизводимым. Он хорошо подходит для анализа данных, потому что его легко разделить на задачи, из которых получатся коммиты. Попробуем сделать это на практике и проанализируем длину клюва антарктических пингвинов.

7.1 Загрузка данных

Загрузите файл с данными penguins.csv и поместите в папку проекта. Чтобы открыть папку в файловом менеджере, в меню на панели Files выберите More → Show Folder in New Window. Когда вернётесь в RStudio, убедитесь, что файл penguins.csv появился на панели Git.

Создайте скрипт для анализа. В меню на панели Files выберите New File → R Script и введите название файла penguins.R

Скопируйте следующий код для импорта данных и сохраните его в созданном скрипте. Выделите обе строки и запустите, нажав кнопку Run в правом верхнем углу редактора RStudio. Если импорт данных работает, в консоли появится вектор из чисел.

data <- read.csv("penguins.csv")
data$bill_length_mm

Убедитесь, что файл скрипта также появился на панели Git. Добавьте оба файла в индекс, отметив галочкой в столбце Staged, и создайте коммит. В окне коммита обязательно проверьте содержимое скрипта penguins.R, так как часто пользователи забывают сохранить файл перед добавлением в индекс.

После создания коммита список измененных файлов на панели Git должен быть пуст.

7.2 Визуализация

Анализ новых данных полезно начинать с исследования распределения. Для этого построим несколько вариантов гистограммы длины клюва с разной шириной столбца. Сохраните приведённый ниже код в тот же файл, запустите и посмотрите графики.

data <- read.csv("penguins.csv")
x <- data$bill_length_mm

hist(x, breaks = seq(40, 60, 4))
hist(x, breaks = seq(40, 60, 2))
hist(x, breaks = seq(40, 60, 1))

Файл penguins.R снова появился в списке изменений на панели Git. Добавьте его в индекс, проверьте изменения в окне коммита и создайте новый коммит с описанием «Добавили гистограммы для длины клюва».

7.3 Экспорт

Гистограмма с шириной столбца 2 выглядит наиболее информативно. Такой график можно и опубликовать. Для того чтобы экспортировать изображение, сохраните следующий код в файл скрипта и запустите его.

data <- read.csv("penguins.csv")
x <- data$bill_length_mm

png("penguins-hist.png")
hist(x, breaks = seq(40, 60, 2))
dev.off()

В списке изменений на панели Git появится файл с изображением penguins-hist.png. Его мы тоже добавим в коммит. Во-первых, так другие участники сразу увидят результат, без необходимости запускать скрипт. Во-вторых, если вы измените ширину столбца или другие настройки графика, будет удобно сравнить старую и новую версии.

Добавьте оба файла в индекс и создайте из них коммит с описанием «Сохранили гистограмму длины клюва».

На этом закончим с созданием коммитов и посмотрим их в журнале Git.

Делайте коммиты часто и не придавайте слишком большое значение планированию. Коммит это не концептуально новая версия проекта, а просто шаг или изменения, которые вы хотите зафиксировать.

Не обязательно добавлять в коммит все изменения сразу или их отменять — они могут оставаться в рабочей папке сколько угодно. Тем не менее старайтесь не копить изменения, потому что тогда версия в репозитории будет отличаться от версии, с которой вы работаете, а значит, теряется смысл системы контроля версий и возникают ошибки.
